# RPG ИИ-Мастер — Dynamic World Alpha 1

Основано на вашем исходном архиве `test-main(1).zip` (ревизия 2026-11-26.6).
Новая ревизия: `2026-11-27.world-alpha1`.

## Что изменилось

- `engine/turn_protocol.py`: потоковый протокол повествования и служебной дельты. Для обычного хода сохранённой серверной партии модель может вернуть повествование и JSON изменений за один вызов. Технический блок скрывается сервером даже при дроблении метки на сетевые чанки. Дельта хранится вместе с черновиком хода и не переносится в итоговую историю. При отсутствующем, некорректном или незавершённом блоке используется прежний запрос `extract_state`. Создание персонажа, ожидающее повышение и старый API без `party_id` сохраняют прежнюю двухэтапную схему. Периодическая свёртка памяти остаётся отдельной фоновой операцией.
- `engine/world.py`: динамический реестр мира с постоянными серверными ID. Виды записей — NPC, существа, предметы, локации, фракции, способности и другие объекты. Это не каталог заранее заданного контента. Новая запись появляется на основании предложения модели и дословной цитаты из рассказа. Обновление использует прежний ID (или совпадение вида и имени для записи без ID). Для двух разных одноимённых существ нужны различимые имена. Мир хранится в `state.world_entities` существующей партии (SQLite), без новой БД и обязательной миграции. Действующие сохранения без этого поля поддерживаются. Реестр наполняется новыми ходами, история задним числом не импортируется.
- При создании боевого существа модель может предложить относительную силу `minor`, `normal`, `dangerous`, `elite`, `legendary`. Сервер назначает HP в пределах диапазона силы; конкретное значение варьируется по ID и сохраняется. Это экспериментальный баланс, не масштабирование под уровень героя. Модель не может изменять эти HP последующими патчами. Для проверки урона с точной привязкой к зарегистрированному противнику сервер рассчитывает HP по броску и сохраняет результат. Урон герою по существующим правилам не изменён. Не каждый сюжетный удар сейчас использует этот механизм: пока только явно привязанные проверки урона.
- В промпт передаётся не вся энциклопедия, а релевантная часть: до 12 записей с бюджетом около 3500 символов (дополнительно к прежней памяти). Приоритет — участники сцены, локация и совпадения с действием. Это простая текстовая выборка, не векторная память.
- В меню и команде `/world` доступна энциклопедия открытого мира с поиском. Просмотр не вызывает API. До 100 найденных записей отображаются за раз; поиск охватывает все локально загруженные записи партии. В записи видны описания и сохранённые HP, если они есть.
- `PRESENCE_LIMIT` можно настраивать через Railway Variables. Старое значение 10 сохранено по умолчанию. Остальные лимиты параллелизма, Gunicorn, платформа, модель, настройки БД, API и оплата не изменялись.

## Установка и безопасный запуск на Railway

1. Сделайте резервную копию Git-репозитория и данных постоянного Volume (`SAVES_DIR`). Скачайте или скопируйте SQLite и JSON штатным способом; для живой SQLite используйте согласованную резервную копию, не копируйте только файл базы во время записи без WAL. Не удаляйте Volume, не пересоздавайте его и не меняйте ключи подписи/владения.
2. Создайте отдельную ветку для проверки или тестовый Railway-сервис с отдельным Volume и копией тестовых сохранений. Распакуйте архив в корень репозитория. В архиве нет `.env`, секретов или пользовательских сохранений. Не заменяйте свои Railway Variables.
3. Railway Variables: оставьте текущие `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL` (ваш фактический идентификатор GPT-6 Luna), `SAVES_DIR` и прочие рабочие настройки. Добавьте по необходимости:

```env
INLINE_STATE_ENABLED=1
INLINE_STATE_EXTRA_TOKENS=700
PRESENCE_LIMIT=10
```

`INLINE_STATE_ENABLED=1` уже включён по умолчанию. Дополнительный бюджет предназначен для JSON, а не для обязательного удлинения повествования. При проблемах установите `INLINE_STATE_ENABLED=0` и перезапустите сервис: снова будет прежняя двухэтапная генерация. Это не отключает реестр мира, который также наполняется через резервный экстрактор. Для полного отката верните предыдущую Git-ревизию; резервную копию сохранений используйте при необходимости. Новое поле состояния не требует SQL-миграции.

4. Разверните ветку. Проверьте `/api/health`: `app_revision` должен быть `2026-11-27.world-alpha1`, `inline_state_enabled` — `true`, если оптимизация включена.
5. Начните тестовую партию или загрузите копию старой. Проверьте знакомство с NPC, новую локацию, создание противника, объявление и выполнение броска урона, покупку, отдых, квест, повышение и перезагрузку страницы. Откройте `/world` и проверьте устойчивость записей. Сравните с прежней версией.
6. Смотрите Railway Logs: `[state] mode=inline` означает успешное применение встроенной дельты без второго вызова модели; `mode=extract` / `state_mode=fallback` означают резервный путь. В `/admin/tokens` сравните число вызовов и суммарный расход токенов на одинаковых игровых сценариях. Если статистика скрыта, существующая переменная `TOKEN_ADMIN_PASSWORD` включает эту страницу.
7. Прежде чем повышать онлайн, измерьте 100–300 типичных ходов, долю inline-ходов, фактическое время до первого текста и полного сохранения, а также ошибки и стоимость. `PRESENCE_LIMIT` не является лимитом API. `LLM_MAX_CONCURRENT` по умолчанию 2, Gunicorn по-прежнему 1 worker / 8 threads. Не поднимайте лимиты сразу до 50 без нагрузочных тестов и согласования API-квот. Тариф Railway за $5 сам по себе не подтверждает достаточность ресурсов.

## Проверки

Локально (после установки зависимостей):

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m compileall -q app.py engine tests
```

В среде подготовки прошло 35 тестов: 20 исходных + 15 новых. Новые тесты проверяют потоковый протокол при разных границах чанков, скрытие невалидного блока, защиту типов, создание/повторное использование объектов, выбор контекста, привязку броска к противнику, обработку старых сохранений, интеграцию функций Flask-маршрутов и SQLite с имитацией ответов модели, повторное сохранение без дублирования. JavaScript проверен `node --check`. Реальные Flask/OpenAI SDK в среде подготовки отсутствовали; для тестов функций использовались минимальные заглушки импортов и поддельный API-поток. HTTP-сервер в реальном браузере и реальный GPT-6 Luna не проверялись. Платных API-вызовов не выполнялось.

## Ограничения и следующие этапы

Это первая рабочая итерация, а не законченный универсальный симулятор. Схема не доказывает, что правильно сформированный JSON отражает все события повествования; пропущенные моделью изменения могут остаться неучтёнными. Цитаты из ответа подтверждают текст, но не гарантируют его истинность. Промпт дополнен правилами, поэтому экономия денег зависит от реального токенизатора, частоты откатов и длины JSON. Скорость 15–20 секунд и поддержка 50 игроков не гарантированы. Для боевых объектов пока есть ограниченный HP-профиль, нет полной системы уникальных эффектов, брони, сопротивлений, заклинаний, ресурсов NPC, AI-планировщика или симуляции мира. Необычные способности можно хранить как описание, но это не значит, что их эффекты автоматически исполняются. Прежние модели извлечения и числовых предложений остаются для действий, которые ещё не перенесены в движок. Не используется выполнение произвольного Python/SQL из ответов ИИ.

Далее: универсальные эффекты с типизированными операциями (урон, лечение, перемещение, изменение ресурса, статусы и длительность); серверное разрешение действий и расчёт цен; более строгая схема и проверка полноты дельт; проверка и расширение боевых правил и памяти; нагрузочные тесты и учёт лимитов; безопасность старых публичных API; гостевой баланс, авторизация и платежи. Регистрация, монетизация и кооператив в эту версию не добавлены.

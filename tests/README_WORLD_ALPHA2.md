# RPG Dynamic World — Alpha 2.1

Обновление Alpha 1. Сохранены прежние маршруты, Railway, SQLite и интерфейс. Старые сохранения не требуют миграции схемы: дополнительные поля находятся в JSON состояния партии. Перед установкой сделайте резервную копию репозитория и Volume. Разверните сначала тестовую ветку. Не удаляйте текущий Volume или переменные API. Не включены ключи API, сохранения и данные игроков.

## Что изменилось в Alpha 2.1

- Разные удары по одной цели суммируются, а повтор той же фразы о попадании подавляется. Если HP уже вычислено подписанным броском, тот же ресурс цели в этом ходе защищён от повторного списания.
- Мирный NPC может получить боевые характеристики, сохранив ID, историю и отношение к герою.
- Явно упомянутые объекты получают приоритет в контексте. Сон, паралич и оглушение ограничивают действия, но часы можно продвинуть командой `/wait`.
- В интерфейсе рассказ появляется после сохранения хода. Если движок отклонил эффект, игрок увидит подтверждённый результат. Простые ходы получают короткие ответы.

Распакуйте ZIP в корень существующего репозитория. Настройки сборки и запуска входят в архив. Проверьте поле `app_revision` в `/api/health` после обновления Railway. Ожидаемое значение — `2026-11-27.world-alpha2.1`. Для длинных сцен предусмотрен потолок `NARRATION_MAX_TOKENS=2300` по умолчанию. Если переменная уже задана в Railway, используется её значение.

## Энциклопедия
`/world` или пункт меню. Категории: Все, Персонажи (NPC), Существа, Предметы, Локации, Фракции, Способности, Прочее. Счётчики, поиск внутри категории, группировка, пагинация по 30 записей. Распространённые английские статусы локализованы при отображении; неизвестные сохраняются как есть. Изменённые формы, отношение, мана и окружение отображаются при наличии. `/effects` или пункт меню показывает активные эффекты, сроки и следующие срабатывания. Эти окна не вызывают API.

## Протокол эффектов
В скрытой дельте `effects` — массив до 12 объектов. Обязательно `type` и `evidence` (точная фраза нового видимого ответа, минимум 5 символов). `name` — произвольное название. Цель `target`: `hero`, постоянный ID объекта, либо однозначная ссылка `{"kind":"creature","name":"Зеркальный волк"}`. Объекты создаются в порядке эффектов или раньше через `world_entities`. Не требуется фиксированный каталог.

| type | Поля кроме type/evidence/name | Поведение |
|---|---|---|
| damage/heal | target, amount 1..300 | ограничение текущим/max HP, лечение не воскрешает |
| modifier | target, stat str/dex/con/int/wis/cha, amount -5..5, duration | временный бонус; для героя применяется к новой проверке с pending_check.stat, сумма ограничена ±10 |
| move | target, destination | перемещение в зарегистрированную локацию; у героя смена сцены |
| control | target, control, duration | сохранённое состояние и срок, передача мастеру; пока не принудительная блокировка всех действий |
| create | entity {kind,name,description,location,traits,threat} | запись в реестре, HP новых боевых существ рассчитывает существующий движок |
| transform | target, form/description/traits | сохраняет новую форму, не переписывает базовую расу/HP героя |
| drain | target, recipient, resource hp/mana, amount | перенос ресурса в пределах доступного объёма и свободной ёмкости получателя |
| environment | target (location), environment/description/traits | сохранение состояния окружения |
| schedule | target, operation damage/heal, amount 1..100, delay, interval, count 1..20 | тики по игровым часам |
| relation | target (npc/creature/faction), amount -30..30 | отношение к герою в диапазоне -100..100 |
| dispel | effect_id | снять активный эффект |

До 40 активных эффектов. Длительность до 30 игровых дней. Повтор одноимённого временного эффекта на той же цели заменяет его. Мана вводится лениво при обращении к ресурсу: если поля отсутствуют, максимум равен max_hp (ограничен 300). Это временное правило Alpha 2; обычная магия пока не списывает ману автоматически. При отсутствии игровых часов временные эффекты отклоняются, пока часы не будут установлены. Тики применяются при сохранении очередного игрового хода, не в реальном времени. Числа предлагает ИИ, сервер валидирует и выполняет арифметику. Подписанные броски остаются приоритетными; несколько самостоятельных эффектов HP и ранее назначенные тики могут сработать в одном ходе. Старый hp_delta используется как резерв, а не складывается с явным изменением HP героя. Неизвестные виды эффекта не исполняются. Необычные сюжетные события можно сохранить через существующий facts без числовой операции. Ошибочные предложения отклоняются по одному, без частичных изменений. Итоги и ошибки появляются в серверной сводке хода.

## Пример составного эффекта
```json
{"effects":[{"type":"create","entity":{"kind":"creature","name":"Теневой страж","threat":"normal"},"evidence":"Теневой страж появился у ворот."},{"type":"control","target":{"kind":"creature","name":"Теневой страж"},"control":"sleep","duration":10,"name":"Сон теней","evidence":"Теневой страж погрузился в сон."}]}
```
Встроенный и резервный экстрактор поддерживают effects. Для длинных блоков можно увеличить `INLINE_STATE_EXTRA_TOKENS` с 700 до 1000–1200 после замера токенов. По умолчанию не изменено. На этапе создания героя эффекты не применяются, чтобы сохранить прежний мастер создания персонажа. Сюжетный текст стримится до проверки дельты; итог сервера может отличаться от обещания модели, что отражается в сводке. Для произвольных способностей еще нет полноценной системы стоимости, перезарядки, проверки сопротивления и боевого ИИ.

## Проверки

Запустите `python -m unittest discover -s tests -v` из корня проекта. Интеграционные тесты имитируют ответы модели. Проверка живой партии на Railway проводится после развёртывания.

# RPG Dynamic World — Alpha 3.1

Стабилизационное обновление поверх предоставленного архива Alpha 3. Существующий интерфейс, серверные приключения, свободный ввод текста, память и OpenAI-совместимый провайдер сохранены. Новых обязательных внешних сервисов нет.

## Изменения

1. `engine/clock.py`: единые часы механических действий. Боевой раунд, успешное отступление и экипировка — 6 секунд; покупка и размен — 60 секунд. `/wallet` и `/shop` не двигают время. Обычный повествовательный ход без явной длительности получает 6 секунд; явное ожидание и подтверждённое повествовательное время сохраняют прежний механизм. `world_minute` остаётся форматом старых сохранений, `world_second` хранит остаток секунды в минуте. Эффекты и сроки событий продвигаются по общим часам.
2. `engine/combat.py` и `engine/effects.py`: бонусы/штрафы характеристик учитываются в атаках героя и NPC, инициативе, отступлении. Действия героя под сном, параличом и оглушением блокируются. Тики яда и истечение эффектов работают в серверном бою; после раунда проверяется здоровье. Эффект перемещения не пропускает в закрытую/ограниченную локацию.
3. `engine/equipment.py`: произвольные имена и проверяемые характеристики предметов. Поддержка в инвентаре и реестре мира. Старый каталог оставлен только как совместимость со старыми предметами. Оружие поддерживает формулу кубиков, стихию и характеристику атаки; броня — КБ и предел бонуса ловкости. Команда `/equip` принимает имя или ID предмета из инвентаря. Для одноимённых предметов предпочтителен ID. Поддерживаются базовые боевые свойства, не произвольный исполняемый код.
4. `engine/world.py`: одинаковые имена больше не означают одинаковый объект. Разные локации или явный `new_entity:true` позволяют создать новый ID; перемещение существующего NPC производится по его ID. Неоднозначное имя в боевой команде требует точного ID. Энциклопедия показывает ID одноимённых записей.
5. `life_state`: сервер различает alive, unconscious, defeated, dead, destroyed. Старые статусы «убит», «погибший», «уничтожен», «мёртв» и другие распознаются. Инициализация боевого HP не воскрешает погибших. Лечение не воскрешает. При 0 HP — defeated; переход к явно подтверждённой гибели сохраняется. Специальная механика воскрешения пока отсутствует.
6. `safe_ability`: проверяет максимально возможный суммарный урон всех попаданий. Для уровня/силы P (1–20) базовый предел равен 10+3P, жёсткий предел — втрое больше. Свыше базового предела обязательны затраты маны и перезарядка; сверхсильные способности отклоняются. Для NPC используется уровень угрозы; у героя — уровень персонажа. Ранее встроенные заклинания сохранены. Это стартовая балансировка боевых формул, а не полный баланс всех возможных эффектов.
7. `engine/economy.py`: предложение сверяется с подтверждающим текстом (товар, цена, валюта и торговый контекст); если указан продавец, проверяются ID, локация, состояние жизни и имя в тексте. Остатки списываются после покупки; цена умножается на количество. `/shop` показывает ID предложения и остаток, `/buy` принимает имя или ID. Для прежних/непривязанных предложений без ID продавца оставлен ограниченный режим совместимости (по умолчанию 1 единица). Проверка текста эвристическая, не доказательство истинности произвольного рассказа.
8. В контекст мастера передаются мана, максимальная мана, оставшиеся раунды перезарядки и доступные механики экипировки/способностей. Старые листы без маны используют исходную формулу ёмкости.
9. `engine/api_budget.py`: постоянный дневной ограничитель всех исходящих попыток генерации, включая fallback, извлечение состояния, резюме и диагностический POST. Вызовы резервируются до отправки провайдеру, атомарно в SQLite; SDK-ретраи отключены, чтобы не обходить счётчик. Старая выдача платных запросов из переданного клиентом состояния выключена по умолчанию; штатное создание и импорт приключений сохранены. `/api/diag` защищён Basic Auth, GET не вызывает модель; платный POST требует пароля. Ограничены размеры HTTP-тела и действия.
10. Добавлены 20 регрессионных тестов. См. TEST_RESULTS.txt.

## Примеры протокола

Новый предмет в `world_entities` (поле `evidence` должно дословно присутствовать в рассказе):

```json
{"kind":"item","name":"Ледяная игла","mechanics":{"slot":"weapon","dice":"2d6+1","element":"cold","stat":"dex"},"evidence":"Кузнец передаёт Ледяную иглу."}
```

Броня: `{"slot":"armor","defense":15,"dex_cap":2}`.

Разные NPC с одинаковым именем: `{"kind":"npc","name":"Орен","location":"Порт","new_entity":true,"evidence":"Другой Орен встречает тебя в порту."}`. Обновлять существующего только по его ID.

Подтверждённое торговое предложение: `{"item":"Паёк","currency":"silver","price":3,"seller_id":"<id NPC>","stock":2,"evidence":"Орен продаёт паёк за три серебряных, в наличии 2 шт."}`.

## Railway: установка

1. Сделайте резервную копию текущего репозитория и Volume (включая parties.sqlite3, token_usage.sqlite3, JSON-сохранения и память). Лучше выполнить обновление в отдельной ветке с копией данных; не тестировать старую и новую версию одновременно на одном томе.
2. Распакуйте архив в корень репозитория, заменив одноимённые файлы. Сохраните существующие Railway Variables для GPT-6 Luna и подключённого Volume. `SAVES_DIR` должен указывать на действующий постоянный том (например `/data`, если именно туда он смонтирован). Секреты в архив не входят.
3. Railway создаст `api_budget.sqlite3` в существующем каталоге сохранений. Старые таблицы приключений не удаляются и не меняют схему. Новые поля JSON заполняются при использовании. Перезапуск не обнуляет дневные счётчики, если Volume постоянный.
4. После деплоя `/api/health` должен сообщать `app_revision: 2026-11-27.world-alpha3.1`. Проверьте импорт старого приключения, свободный ход, бой, яд, экипировку, торговлю и повторное открытие.

### Новые переменные (необязательны; показаны значения по умолчанию)

```env
API_ENABLED=1
API_DAILY_CALLS=3000
API_OWNER_DAILY_CALLS=150
API_DAILY_UNITS=30000000
ALLOW_LEGACY_LLM=0
```

`API_DAILY_CALLS` — общий максимум попыток генерации за сутки UTC. `API_OWNER_DAILY_CALLS` — на гостевого владельца в контексте HTTP-запроса; фоновое резюме входит в общий лимит. `API_DAILY_UNITS` — дополнительный общий лимит условных единиц: UTF-8 байты текстового контекста + запрошенный лимит вывода. Это консервативный измеритель нагрузки, не точные токены и не денежный бюджет. Все значения нужно выбрать под свой реальный расход и лимиты AIAI.BY. Попытки с ошибками не возвращают резерв автоматически. `API_ENABLED=0` отключает генерацию аварийно. Для диагностики установите надёжный `TOKEN_ADMIN_PASSWORD`; GET показывает настройки, POST дополнительно выполняет платную проверку. Без пароля маршрут скрыт (404).

При импорте старых локальных сохранений используйте штатное создание серверного приключения через UI. Не включайте `ALLOW_LEGACY_LLM=1` на публичном сайте: это временная совместимость старого API, принимающего состояние от клиента. Гостевой лимит можно обойти новой cookie, но не глобальный дневной ограничитель. Это не антибот-система, не баланс оплаченных ходов и не гарантированный денежный предел провайдера. Защита всех старых маршрутов JSON-сохранений и полноценная авторизация остаются задачей до коммерческого запуска.

## Тестирование

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m compileall -q .
```

90 тестов обнаружено: 88 пройдено, 2 HTTP-теста пропущены (в среде проверки не установлены Flask и OpenAI SDK; установка зависимостей недоступна). Тесты с имитацией модели и локальной SQLite прошли. JavaScript проверен командой `node --check` на извлечённом скрипте. Реальные вызовы AIAI.BY, живой браузер и Railway не проверены. Не утверждается, что достигнута пропускная способность на 50 игроков.

## Что ещё предстоит

- Полная синхронизация свободного текста с подтверждённым результатом движка до отображения повествования; свободный текст пока по-прежнему использует протокол дельт и резервный анализ. Повествовательные действия не полностью сведены к серверным командам.
- Расширение конструктора экипировки и составных способностей, групповые бои, жизнь мира, воскрешение как специальное правило, окончательный баланс.
- Полноценные HTTP/E2E и нагрузочные проверки с реальным провайдером, измерение задержек, гостевые пробные ходы, подписки, коммерческая безопасность.
